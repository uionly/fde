<CustomerScenario title="Northstar field assignment — synthetic">
Northstar wants one assistant to search policies, inspect accounts, and create support tickets. The first proposal exposes a generic SQL tool and assumes the protocol makes it safe.
</CustomerScenario>

## Name the capability boundary

MCP uses a host, clients, and servers. A host coordinates the AI experience; a client maintains a connection to a server; a server exposes capabilities such as tools, resources, and prompts. That structure standardizes exchange, but does not determine the customer permissions for an account or ticket. Design those permissions explicitly.

For this customer, expose search_policy, read_account_summary, and propose_ticket as separate, bounded capabilities. Define required fields, allowed values, output limits, and typed errors. Avoid passing a raw database connection string or allowing the model to invent arbitrary SQL. A resource can expose reference context; a tool can perform an operation. Review the effect and sensitivity of every capability rather than classifying all protocol traffic as equally safe.

## Negotiate and test the contract

Record the protocol revision and supported capabilities in your integration brief. Do not assume every host supports every server feature. Test initialization, unavailable capabilities, malformed inputs, empty results, and downstream timeouts. Keep protocol concerns in an adapter so changes do not spread through the customer application.

A successful tool response is still untrusted application input. Validate its shape, bound its size, and preserve source identity where a later answer needs evidence. A document returned by a server is not an instruction to override the user’s task. Use deterministic policy checks for writes and explicit approval where the customer action requires it. The protocol connection should make a narrow capability understandable, not expand what the agent is allowed to do.

<FDEPrinciple>
The protocol does not replace authorization or task-specific effect controls.
</FDEPrinciple>
